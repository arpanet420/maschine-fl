# Project review, 2026-11-05

A pass over the whole project from top to bottom: the automated checks, the hardware layer, the FL
protocol and state, the FL script, every page, rendering, the daemon, packaging and the docs, then
randomised tests of all of it.

`npm run check` passes (1331 vitest tests, 412 FL script tests). **None of what is under "Fixed" has run on the
MK3 or in FL Studio yet.** To pick it up, reload the FL script (View → Script output → tab MK3 Bridge → Reload
script) and restart mk3d.

## Fixed

### What a player would notice

1. **A light from the last page stayed on.** The LED state was never cleared between frames, so a page only
   turned off what it knew about. ARROW RIGHT stayed lit in 58 page changes (CHANNEL to ARRANGER, MIXER to
   BROWSER and so on), and the 4D arrows after BROWSER. `updateLeds` in `src/main.ts` now starts each frame
   blank; the sender compares whole reports, so this adds no USB traffic. `main.ts` has no automated test: this
   was verified by a scratch test that paints the pages in the same order.
2. **Knobs jumped after a replug.** The MK3's counters restart when it comes back, and the first report was
   read as a big turn. `src/hw/input.ts` (`deviceLost`) now takes it as the new baseline. Buttons still compare
   with what they were, so SHIFT and ERASE get their release.
3. **On SETTINGS, display buttons acted on the page behind.** With CHANNEL behind, display 2 and 3 toggled solo
   and the plug-in window; with MIXER behind, they selected tracks. `src/modes/settingsPage.ts`.
4. **On BROWSER's PLUG-INS tab, display 5 and 6 stepped presets** though nothing was drawn above them.
   `src/modes/browserPage.ts`.
5. **Overlapping chords cut shared notes.** Letting go of one pad ended a note another held pad still played.
   `src/modes/padState.ts` now counts the pads per note.
6. **A LOCKed NOTE REPEAT's pad did not flash with its page closed.** `src/modes/pageStack.ts`.
7. **Long names ran off the screen** in the band of a touched knob and on the SHIFT + pad card (found by the
   fuzz; plug-in values, channel and mixer names). `src/modes/draw.ts`, `src/modes/quickEdit.ts`.
8. **The DOUBLE card stayed up** until something else redrew the page; it now takes itself down after 4 s.
9. **BROWSER offered LOAD when the current preset is unknown.** No tab and no LED now.
10. **STEP said `Pattern 1  Pattern 1`** when a pattern has FL's default name (seen in the page images).
11. **Chords with no name showed `F?`**: 137 of 1248 pad, scale and type combinations, including Sus4 on the
    fourth degree of Major. They now show their notes, `F B C`.
12. **Projects at another PPQ than 96 had wrong positions**, LOOP, NOTE REPEAT and LIVE. SONG_POS now carries the
    PPQ (`docs/sysex.md`). An old script with a new mk3d, and the reverse, both still work.
13. **GRID's saved snap** was only written when something else saved the page state; it is now saved when it
    changes.

### The daemon, the script and the tools

14. `RedrawQueue` (`src/render/screens.ts`): no redraw is lost while a frame is being sent. ACTIVITY no longer
    redraws the screens.
15. No USB lookups and no `screen update failed` line while the MK3 is away (seen in the daemon's real log).
    `--png` now also writes without a device.
16. Shutdown cannot hang (3 s limit), and SIGHUP shuts down cleanly like SIGINT and SIGTERM (a screen transfer
    must not be cut off midway).
17. The fault bar draws at once, without looping on a fault that repeats on every draw. `src/fault.ts`.
18. `withScreenBrightness` refuses a report with the wrong id; a failing `HID.devices()` no longer escapes.
19. FL's fonts are found for FL versions newer than the ones listed. `src/platform.ts`.
20. FL script: FL's callbacks log each error once instead of every time.
21. `scripts/winsync.sh`: a tracked file that was deleted locally no longer stops the copy.
22. `npm run pagepng` also draws CHANNEL, PLUG-IN, MIXER, STEP, PAD MODE, MUTE, SELECT, SOLO and DUPLICATE, and
    removes its old images first. `stackHarness` now has every page `main.ts` has.
23. Tidying: one definition of `STEPS_PER_BAR` and `BEATS_PER_BAR` (`src/fl/protocol.ts`); shared `clamp`,
    `clamp7`, `hitVelocity`, `DISPLAY_BUTTONS`, `GROUP_BUTTONS`; dead helpers, constants and imports removed.
24. Docs compared with the code and corrected: `setup.md`, `mapping.md`, `sysex.md`, `protocol.md`, `fl-ilmcp.md`,
    `workflow.md`, `README.md`, `PLAN.md`, `handoff.md`, `CLAUDE.md`. `sysex.md` and the script's command table
    agree, 76 rows each. Internal links resolve.

New test files: `test/playPosition.test.ts`, `test/redrawQueue.test.ts`, `test/textFits.test.ts`.

## How it was tested

| Test                                    | Size                                                  | Result                                                               |
| --------------------------------------- | ----------------------------------------------------- | -------------------------------------------------------------------- |
| Random input through the real pages     | 2900 runs of 800 steps                                | Two text overflows (7 above). No exceptions, stuck overlays, hanging notes, bad MIDI, bad LED values or leftover timers |
| Random frames and callbacks in the script | 60 runs of 400 steps                                | Nothing escaped, never over 8 frames per callback, every frame valid |
| Script's frames through the TS decoder  | 2668 unique frames                                    | All decode and re-encode byte for byte                               |
| Garbage to both SysEx decoders          | 500,000 frames                                        | Nothing thrown                                                       |
| Garbage to the HID parser               | 400,000 reports, with device losses                   | Nothing thrown, every event in range                                 |
| **Pages and script joined end to end**  | Over 1000 runs of 300 steps                           | Clean, see below                                                     |
| Every knob and display button on every page | With CHANNEL, MIXER, ARRANGER and PLUG-IN behind  | 3 and 4 above, and question 2                                        |
| `pages.json` with junk in it            | 2000 files                                            | Pages start, draw and work; nothing thrown                           |
| Damaged NKS, plug-in database and cache files | 220,000 inputs                                  | Plain errors the index catches, nothing slow                         |
| Every page by eye                       | 67 scenes from `npm run pagepng`                      | 10 above, and question 3. The layout rule holds on all of them       |

The end-to-end run presses random controls on the real pages, sends their SysEx through the real FL script
and a fake FL, and feeds the answers back, so both sides see one project. Meanwhile "someone" uses FL with the
mouse: deletes channels and patterns, renames channels (non-ASCII, emoji, 300 characters, empty), loads a
project and reloads the script. After settling, mk3d's state must match FL's. It did, except names cut at 32
characters and control characters dropped, both by design. With everything let go, the only traffic in 5 s was
one ALIVE a second, so there is no feedback loop between the two sides.

The limit of all this: it is a fake FL and no USB timing. It finds logic errors, not how FL or the MK3 really behave.

## Measured

- A redraw costs 0.05–0.63 ms to draw and 0.7–1.0 ms to flush per frame, without USB.
- `FlPluginDb.load`: 421 names in 238 ms, then 66 ms. The NKS cache of 28 products loads fine.
- **The script's full re-read makes 308 FL calls every 100 ms** with 24 channels (11 in an idle pass), about 3000
  calls a second on FL's UI thread. Counted against the fake FL; the real cost is unknown (question 11).

## Left as it is, on purpose

- Reopening the screens' USB on a failing frame: a backoff could lose the only redraw after a replug. Look again
  on Windows, where every frame can fail the same way.
- `LiveOverlay` doesn't send `TLC_Release` for a held scene on device loss (rare).
- `double_channel`, the fallback when `duplicatePatternData` is missing, also copies param 7, which is an absolute
  tick on recorded notes. The DOUBLE card says `notes copied` on that path too.
- LOCK stays on after a device loss though the notes stop.
- Script parameter keys include the channel name, so anchors are lost after a preset rename; `param_units` grows
  slowly.
- SONG_POS always counts 16 steps a bar, so bar numbers are wrong in other meters (question 8).
- Windows, for that stage: `HID.devices(...)[0]` may pick the wrong collection; NKS discovery paths are
  macOS-only; Documents may be redirected.
- Stricter TypeScript flags: `noImplicitOverride` would need 32 `override`s, `exactOptionalPropertyTypes` gives 17
  errors. Not worth it now.
- Dependencies: `npm audit` is clean. Newer majors exist (TypeScript 7, vitest 5.1, eslint 10.14, canvas 1.1).

## Questions for the owner

1. **Commit all this?** It is one large uncommitted change, nothing pushed.
2. **Should a page swallow the knobs, 4D and arrows it doesn't use?** Today they reach the main page behind it:
   with CHANNEL behind, turning the 4D on any overlay or tool page except NAVIGATE and LOOP selects another
   channel, and pushing it (LOOP too) opens the plug-in window. ARROW RIGHT stays lit from the page behind, and a
   press changes that page unseen: hold MUTE, press it, and MIXER has moved to its next bank when MUTE closes.
   This is documented and deliberate (`docs/mapping.md`), but goes against "a control acts on the page it is on".
   Recommended: swallow them. A dry run shows it is one `if` in `PageStack.dispatch`, and 1 test changes.
3. **Remove these texts as filler?**
   - SCENE: `A pad jumps now`, `A pad jumps at the next bar`, `NOW is on`, `NOW is off: jumps wait for the bar`,
     and `No markers` on both screens.
   - LOOP: `4D turn moves the loop`, `Loop is off (OFF = SHIFT + RESTART)`.
   - NOTE REPEAT and ARP: `120 BPM, free running` / `locked to FL's grid`, `Hold keys to repeat` / `arpeggiate`.
   - DUPLICATE: `press a pad to duplicate`.
   - BROWSER: `PUSH 4D TO LOAD`, the picker's help lines, `PUSH PLUG-INS (display 2) TO OPEN FL'S PLUGIN PICKER`,
     the unknown preset's text.
   - NAVIGATE: the `Focus` column, which repeats the tile.
   - FILE: `Last here`, and the undo hint on both screens.
   - SETTINGS: `velocity by hit value`, and brightness three times on one screen.
   - PLUG-IN: `Page 1` as both tab and title, and `page 1 / 1`.
4. **Should SHIFT + DUPLICATE double like Maschine?** DOUBLE works now on PATTERN (`doublePattern`). SHIFT +
   DUPLICATE still clones the pattern.
5. **Remove trial and probe code?** `double_pattern_native` and its flag; `addMarker`, `playlistView`,
   `setSongPos`, `picker` (no sender in mk3d); browse actions other than `pluginPicker`; the setters' PROBE lines
   (probe lines are 180 of 1000 lines in a real log); `_ilmcp`, `_probe_*`, the guessed `getBlockSetStatus`.
6. **What should ERASE and STEP do on recorded channels?** `setGridBit` doesn't write piano roll notes while
   `getGridBit` shows them as on. Needs a test on the hardware.
7. **Do chords show in KEYBOARD's flashing pads?** PLAYED_NOTES has only been checked with one note per step. CHORDS
   doesn't flash yet.
8. **Do you work in other meters than 4/4?** If so, bar numbers need `general.getRecPPB()`.
9. **Rename `INPUT Q`?** GRID's tab turns FL's snap on and off; the name came from Maschine and may mislead.
10. **A licence for the repo?** Needed before sharing code with Encdr's author. What should we ask them?
11. **Measure the 308 FL calls per 100 ms inside FL?** A small timer in the script would show whether it matters.
12. **Keep the randomised tests in the repo?** They are not committed; they are in `out/fuzz-tools.tgz`
    (gitignored) with paths for this machine. A small seeded one as a test file would run in about a second.
13. **Should `Fifth` be a real fifth in pentatonic scales?** It goes 4 scale steps up, so in Major pentatonic C
    gives C and A. Check what Maschine does.
14. **Is display command `0x01` confirmed?** `docs/protocol.md` still says "not yet confirmed here", though it has
    been in daily use since 2026-11-04.
